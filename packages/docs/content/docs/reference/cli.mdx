The Everr CLI queries local telemetry and remote Cloud or self-hosted installations, inspects GitHub Actions CI runs, manages bundled skills, and reconciles resources as code. Run `everr --help` or `everr <command> --help` for the help included with your installed version.

## Authentication and remote queries

- `everr login`: authenticate in your browser and save a connection profile
  - `--url <app-url>`: connect to a self-hosted installation or another app URL. Without this flag, login uses the selected profile or repository target, falling back to `https://app.everr.dev`.
  - `--organization-id <id>`: require approval for a specific organization. It must agree with an existing target.
  - `--profile <name>`: save the login under a custom name or reauthenticate that profile
  - `--no-open`: print the authorization URL without opening a browser
- `everr logout [--profile <name>]`: revoke the selected session and remove its saved credentials, keeping the profile's connection settings
- `everr whoami [--json]`: show the effective profile, selection source, installation URL, account, organization, and advertised ingestion endpoint
- `everr query "<SQL>"`: run read-only SQL against the selected installation
  - `--format <json|ndjson|table>`: choose the output format (default: `table` in a terminal, `ndjson` otherwise)

CLI sessions authenticate queries and resource management. Application exporters use separate ingestion keys. During exporter setup, `everr whoami --json` returns `ingestEndpoint`, the installation's OTLP/HTTP base URL. Save that URL in your exporter configuration. A null endpoint means the server has not advertised one; app and ingestion URLs can differ.

## Profiles

A profile names an installation, organization, and account. Keep multiple profiles to use different installations, organizations, or accounts without replacing other logins.

| Command | Purpose |
| --- | --- |
| `everr profiles list` | List saved profiles, marking the global default with `*` |
| `everr profiles show <name>` | Show one profile's connection metadata without credentials |
| `everr profiles use <name>` | Set the global default profile |
| `everr profiles remove <name>` | Delete a profile and its saved credentials locally |

Profile management commands operate on local files. A listed profile's `authenticated` status means credentials are saved; it does not check whether the server still accepts them. To revoke a session before removing a profile, run `everr logout --profile <name>`. There is currently no profile rename command.

Unless you supply `--profile` during login, names come from the organization name: `Everr Labs` becomes `everr-labs`. Collisions with another installation add the hostname; remaining collisions add `-2`, `-3`, and so on. Logging into the same installation, organization, and account reuses an existing profile. Existing profile names are preserved. The first saved profile becomes the global default; its name does not determine which profile is the default.

Remote commands select a profile in this order:

1. `--profile <name>` for this command.
2. The `EVERR_PROFILE` environment variable.
3. A profile matching the repository's `.everr/config.yaml` installation URL and organization ID.
4. The global default, when no repository target is configured.

For example:

```sh
everr login --url https://observability.acme.com
everr profiles list
everr profiles use acme
everr --profile staging resources list
```

Use the names printed by login or `profiles list`. Profile names may contain letters, numbers, dots, underscores, and hyphens. Changing the global default does not override a repository target. If a repository has no matching profile, or several profiles match, the command fails rather than selecting another target. Use `--profile` to resolve an ambiguous selection. Logged-out or expired credentials require login for that profile.

### Repository targets and credential storage

Successful login from a Git repository creates `.everr/config.yaml` at its root when no project configuration exists:

```yaml
version: 1
url: https://observability.acme.com
organizationId: org_123
```

This file records the shared remote destination without credentials or a profile name, so it can be committed for teammates using their own accounts. Login preserves existing project configuration. Lookup walks from the current directory to the nearest Git root, including worktrees, and uses the nearest configuration file. Outside a Git repository, login saves only the user profile. The `.everr/` target directory is separate from the conventional `everr/` resource directory used by `apply`.

User profiles are stored in `config.yaml` and session credentials in `credentials.json`, under `~/Library/Application Support/everr` on macOS or `${XDG_CONFIG_HOME:-~/.config}/everr` on Linux. `EVERR_CONFIG_DIR` overrides this directory and must be an absolute path. Debug builds use `config-dev.yaml` and `credentials-dev.json` and default to `http://localhost:5173` when no login target is configured.

## Cloud

- `everr cloud login`: compatibility command for `everr login`, using the same profile selection
- `everr cloud logout`: compatibility command for `everr logout`
- `everr cloud status`: check the current session and print the user's name, email, organization, and Cloud URL
  - Prints `Name:`, `Email:`, `Organization:`, and `Cloud:` rows. Missing or expired sessions and request failures produce an error without changing the saved session.
- `everr cloud query "<SQL>"`: compatibility command for `everr query`, targeting the selected installation
  - `--format <json|ndjson|table>`: choose the output format (default: `table` in a terminal, `ndjson` otherwise)

## Maintenance

- `everr upgrade`: upgrade the CLI and its bundled local browser UI
- `everr uninstall`: remove local Everr state and globally installed skills, then print the command that removes the CLI binary

## Skills

- `everr skills list [--project|--global] [--agent <codex|claude-code|cursor|all>]`: list bundled Everr skills for a scope and Agent
- `everr skills install [--all] [--project|--global] [--agent <agent>] [--dry-run]`: install all bundled skills. In an interactive terminal, omitted choices are prompted with project scope selected by default. In a non-interactive context, `--all` is required and the scope defaults to the project. Use `--global` to explicitly install across projects.
- `everr skills update [SKILL]... [--project|--global] [--agent <agent>] [--dry-run]`: update bundled skills already installed in the selected scope. With no scope, update matching installations in both project and global scopes.
- `everr skills uninstall [SKILL]... [--all] [--project|--global] [--agent <agent>] [--yes] [--dry-run]`: uninstall named bundled skills. `--all` requires `--yes`.

The `--agent` option can be repeated. With no Agent filter, a command targets all supported Agents.

## CI

- `everr ci status`: show CI status for the current commit
  - `--commit <sha-or-ref>`: target another commit
  - `--run-id <id>`: target a GitHub Actions run ID
  - `--branch <name>` and `--repo <owner/name>`: override repository context

- `everr ci watch`: watch the current commit's CI runs until completion, then exit non-zero if any run was unsuccessful
  - `--commit <sha-or-ref>`: target another commit
  - `--run-id <id>`: target a GitHub Actions run ID
  - `--attempt <n>`: target a specific run attempt
  - `--branch <name>` and `--repo <owner/name>`: override repository context
  - `--fail-fast`: exit as soon as a CI run completes unsuccessfully

- `everr ci runs`: list recent CI runs
  - `--repo <owner/name>`: filter by repository
  - `--branch <name>` or `--current-branch`: filter by branch
  - `--conclusion <value>`: filter by conclusion
  - `--workflow-name <name>`: filter by workflow
  - `--run-id <id>`: filter by GitHub Actions run ID
  - `--from <expr>` and `--to <expr>`: restrict the start time using [date math](/docs/reference/datemath), for example `now-7d`
  - `--limit <n>` and `--offset <n>`: paginate results (`--limit` defaults to 20 and accepts 1 through 100)

- `everr ci show <trace-id>`: show a CI run's jobs and steps
  - `--failed`: show only failed jobs and their failed steps

- `everr ci logs <trace-id> --job-name <job> --step-number <n>`: print logs for one CI step (the last 1000 lines by default)
  - `--job-name <job>` or `--job-id <id>`: select one job
  - `--step-number <n>` or `--log-failed`: select one step
  - `--tail <n>`: print lines from the bottom
  - `--limit <n>` and `--offset <n>`: fetch a raw page from the top
  - `--egrep <pattern>`: keep only lines matching a RE2 regex, exiting non-zero when no lines match
  - `--color`: preserve ANSI color codes (stripped by default)

## Local telemetry

Local commands and the local browser UI operate independently of remote profiles. They do not read repository targets or profile credentials, ignore `EVERR_PROFILE`, and reject an explicit `--profile`. The local UI has no remote account or sign-in controls.

- `everr local start`: start the local collector and browser UI in the foreground
  - `-d`, `--detach`: run in the background and return once ready. The instance survives closing the terminal; stop it with `everr local stop`. Detached mode does not start at boot or automatically restart a crashed supervisor.
  - `--no-open`: start without opening a browser
  - `--quiet`: suppress startup output and browser launch
  - Prints `otlp:`, `sql:`, and `ui:` URLs once ready. In a terminal, successful startup also shows the Everr banner. Redirected output contains only the endpoints and, for detached startup, a `log:` path. Ctrl+C stops a foreground instance started by this invocation.
  - If a matching collector and UI are already ready, prints their endpoints and exits successfully. An existing foreground instance still needs its original terminal session.
  - Occupied ports and partial or mismatched instances produce an error. Existing processes remain running.
- `everr local stop`: gracefully stop the recognized foreground or detached instance and wait for telemetry to flush and cleanup to finish
  - Keeps collected telemetry data and succeeds when already stopped.
- `everr local status`: check the identity and readiness of the local collector and browser UI, and print their endpoints when running
  - Distinguishes running, starting, stopped, unrecognized listeners, connection failures, and mismatched instances.
  - Exits with code 0 when both belong to the same ready instance, or code 2 otherwise.
- `everr local query "<SQL>"`: run read-only SQL against local telemetry
  - `--format <json|ndjson|table>`: choose the output format (default: `table` in a terminal, `ndjson` otherwise)
- `everr local ui`: open the running local UI in the default browser and print `ui: <url>`
  - Requires the same matching ready collector and UI instance as `local status`. Otherwise, reports the same diagnostics and exits with code 2, without starting services.
  - If browser launch fails, exits with code 1 and prints the URL to open manually.
- `everr wrap -- <command>`: run a command and capture its stdout, stderr, and exit status as local logs
  - The command only starts when the local Collector is available.
  - The CLI preserves the command's exit code.

Detached diagnostic logs are stored in `~/Library/Logs/everr/local.log` on macOS or `$XDG_STATE_HOME/everr/local.log` on Linux (default `~/.local/state/everr/local.log`). Set `EVERR_LOCAL_LOG_DIR` to override the directory. Logs rotate at 5 MiB, keeping three backups. These diagnostic logs are separate from collected application telemetry.

## Resources as code

### Apply

`everr apply <dir>` reconciles the Dashboard, Alert, and Runbook definitions under a directory with Everr. Files can use `.yaml`, `.yml`, or `.json` and are discovered recursively. Apply creates and updates definitions present in the directory and deletes live resources that were previously applied by the same Repoid but are now absent.

By convention, use an `everr/` directory with files such as `*.dashboard.yaml`, `*.alert.yaml`, and `*.runbook.yaml`. The `kind` field, not the filename suffix, determines the resource kind. `kind: Notebook` and the `*.notebook.yaml` suffix remain supported for compatibility, but Runbook is the current name.

The Repoid is inferred from the repository's `origin` remote and normalized to `host/owner/repo`. An optional `everr.yaml` or `everr.yml` Manifest at the apply root can override it with a single non-empty `repoid` key. See [Observability as code](/docs/concepts/observability-as-code).

- `<dir>`: directory to read recursively, for example `./everr`
- `--preview [NAME]`: reconcile into a preview instead of live state and print a shareable link. `NAME` defaults to the current branch and must be explicit in CI or a detached HEAD. Previews do not prompt, never send alert notifications, and expire seven days after their latest apply.
- `--dry-run`: compute and print the diff without writing
- `--yes`, `-y`: skip confirmation for a live apply (required in non-interactive contexts)
- `--adopt`: adopt resources in the applied directory that another Repoid currently owns. Use `--dry-run` first to review the ownership changes.

Apply uses the selected profile's saved session by default. For unattended runs, set `EVERR_API_KEY` to an Organization API Key with the `apply` capability; `EVERR_API_TOKEN` remains a deprecated alias. The URL comes from the selected profile, repository target, or an explicit `EVERR_API_URL`. An explicit URL must agree with an explicitly selected profile or repository target. Without either, an explicit URL targets that installation independently of the global default.

### Inspect and manage live resources

- `everr resources list [--kind <dashboard|runbook|alert>] [--repoid <id>] [--json]`: list live resources across the active Organization. Pass an empty `--repoid` value to select UI-created resources.
- `everr resources show <kind> <slug> [--project <name>] [--json]`: print a resource's stored YAML, or raw JSON with `--json`
- `everr resources delete <kind> <slug> [--project <name>]`: delete a live resource immediately, without prompting
- `everr resources adopt <kind> <slug> [--project <name>] [--yes]`: adopt a live resource into the current repository's Repoid. Interactive terminals prompt for confirmation; non-interactive contexts require `--yes`.

`--project` defaults to `default`. These commands require the selected profile's saved session and do not accept `EVERR_API_KEY`.
