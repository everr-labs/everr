## Overview

Everr exposes a read-only [MCP](https://modelcontextprotocol.io) server so AI clients (Claude, Cursor, the MCP Inspector, …) can query your organization's telemetry directly. It is intended for cases the CLI and skills don't cover: ad-hoc, model-driven exploration.

## Endpoint

|           |                             |
| --------- | --------------------------- |
| URL       | `https://app.everr.dev/mcp` |
| Transport | Streamable HTTP             |
| Auth      | OAuth 2.1                   |

## Tools

Both tools are read-only.

### `query`

Runs one read-only ClickHouse SQL query (`SELECT`, `WITH`, `DESCRIBE`, `SHOW`, or `EXPLAIN`) over your organization's traces, logs, metrics, CI runs, and alert history. Queries only see your organization's data, so they never filter on a tenant.

| Input | Type   | Description          |
| ----- | ------ | -------------------- |
| `sql` | string | The query, required. |

The result is ClickHouse's `JSONCompactEachRowWithNamesAndTypes`: a line of column names, a line of column types, then one JSON array per row. It holds at most 200 rows and about 60,000 characters, values longer than 2,000 characters are cut, and queries time out after 30 seconds. The tool's description carries the table schema and starter queries, the same ones as the `everr-use-telemetry` [skill](/docs/reference/skills).

### `whoami`

Returns the Everr user and the organization the connection is authorized for. It takes no input.

## Authorization

Clients find the authorization server from the OAuth protected resource metadata (RFC 9728) at `https://app.everr.dev/.well-known/oauth-protected-resource`, and register themselves with dynamic client registration.

| Scope                | Grants                                         |
| -------------------- | ---------------------------------------------- |
| `observability:read` | Running the tools, required                    |
| `offline_access`     | A refresh token, so the client stays connected |

You pick the organization on the consent screen, and the access token works for that organization only. Removing someone from the organization revokes their access on their next request.

## Connecting a client

**Claude Code**

```shell
claude mcp add --transport http everr https://app.everr.dev/mcp
```

Then run `/mcp` in a session to complete the browser login.

**Claude Desktop**: Settings → Connectors → Add custom connector → paste `https://app.everr.dev/mcp`.

**Codex CLI**

```shell
codex mcp add everr --url https://app.everr.dev/mcp
codex mcp login everr
```

The login command opens the browser OAuth flow.

**Codex Desktop**: Settings → Integrations & MCP → MCPs → Add a new server → paste `https://app.everr.dev/mcp`.

**OpenCode**

```shell
opencode mcp add everr --url https://app.everr.dev/mcp
opencode mcp auth everr
```

The auth command opens the browser OAuth flow.
