title: Browser telemetry
description: Send OpenTelemetry from a web page to Everr with a public, origin-bound key. Hand the wiring to your coding agent, or set it up yourself.

Everr accepts OpenTelemetry (OTLP) straight from the browser. Because anything in a web page is visible to every visitor, browser ingestion uses a **public key**: safe to ship in page source because it only works from the origins you allowlist, and it can do nothing but send telemetry.

## Set it up with your coding agent

The fastest path is to mint a public key (below), then let your coding agent wire up the SDK. With the Everr skills installed, paste it this prompt:

> Instrument this web app with the OpenTelemetry web SDK and send traces, logs, and metrics to Everr at `https://ingest.everr.dev/v1/traces`, `/v1/logs`, and `/v1/metrics`. Authenticate with the public key in the `EVERR_PUBLIC_KEY` env var, batch the exports, and register the provider at app startup.

Your agent writes and wires the SDK. You only mint the key and drop it in an env var. Prefer to do it by hand? The steps are below.

## Mint a public key

In the Everr dashboard, open the user menu (top-left), click **API keys**, then **New key**.

1. Turn on **Public browser key**.
2. Add every origin your app is served from, one per line, for example `https://app.example.com` or `http://localhost:5173`. An origin is scheme://host with an optional port, and no path.
3. Create the key and copy it. Origins cannot be edited later; to change them, mint a new key and rotate the value in your frontend config.

## Configure the OTel web SDK

Point any OpenTelemetry web SDK at Everr with the key as a bearer token:

```ts
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-http";
import {
  BatchSpanProcessor,
  WebTracerProvider,
} from "@opentelemetry/sdk-trace-web";

const exporter = new OTLPTraceExporter({
  url: "https://ingest.everr.dev/v1/traces",
  headers: { Authorization: "Bearer <your-public-key>" },
});

const provider = new WebTracerProvider({
  spanProcessors: [new BatchSpanProcessor(exporter)],
});
provider.register();
```

Logs and metrics work the same way with the matching exporters (`/v1/logs`, `/v1/metrics`). Requests from an origin that is not on the key's allowlist return **401 Unauthorized**, and the SDK drops the batch.

## Why a public key

A public key differs from a regular (secret) key in three ways:

- It only authenticates requests from one of its **allowed origins** (the browser's `Origin` header must match exactly).
- It is **browser-only**: requests without an `Origin` header are rejected, so it cannot be used from servers or CLI tools.
- It is locked to the **Send telemetry** capability. It can never manage resources with `everr apply` or act on any other API.

Secret keys are the mirror image: they keep working for servers and collectors, and they are always rejected for requests that carry a browser `Origin` header. A leaked secret key cannot be replayed from a website.

## Local development

The local Everr collector (started by the CLI and the desktop app) accepts browser OTLP on `http://127.0.0.1:54318` with no key and no origin setup. Public keys only matter for sending browser telemetry to Everr Cloud.
