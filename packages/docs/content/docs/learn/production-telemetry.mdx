---
title: Send production telemetry
description: Prepare ingestion keys and send production application telemetry to Everr Cloud.
---

Reuse your verified local instrumentation in production: create an ingestion key, configure the deployed application's OpenTelemetry exporter for Everr Cloud, and confirm telemetry arrives. Keep development configured for the local collector. The local Everr collector never forwards data to Cloud.

## Mint an API key

From **To production** in the Home onboarding, select **Create ingestion key** for a server. The **Send telemetry** capability is preselected. For browser applications, use **Create public browser key** and restrict it to your application's origins. You can also open **API keys** from the user menu and create a key there.

An organization admin or owner must create keys. Other members can continue with an existing key supplied through their deployment's secret manager.

- Select the **Send telemetry** capability: it's what lets the key authenticate OTLP requests.
- The full key is shown only once, at creation time. Copy it into your secret manager; you can't retrieve it later.

Never paste server keys into agent prompts or commit them to your project. See [Browser telemetry](/docs/guides/browser-telemetry) for public browser keys.

## Follow your setup's production instructions

The `everr-setup-telemetry` command used for local setup also provides production instructions in its final response and in your project's README, under **Telemetry**. Follow those instructions to configure the ingestion key, select the Cloud endpoint, build or redeploy, and verify fresh telemetry. They identify the settings consumed by your application's actual instrumentation and any code changes still needed.

The production OTLP/HTTP endpoint is `https://ingest.everr.dev/`, also shown in the Home onboarding. Provide credentials through your secret manager or deployment configuration. For manual configuration, follow the steps below.

## Point your service at Everr Cloud

In your deployed service, set the standard OpenTelemetry exporter environment variables to send to Everr Cloud, with your API key as a bearer token:

```sh
export OTEL_EXPORTER_OTLP_ENDPOINT="https://ingest.everr.dev"
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer <your-api-key>"
```

Most OpenTelemetry SDKs and the Collector read these automatically.

If your production infrastructure already runs its own OpenTelemetry Collector, configure that collector's exporter. This is separate from Everr's local collector.

## Confirm telemetry arrives

Trigger the instrumented path in production (a request, a deploy, a scheduled job), then check the Everr dashboard for traces, logs, or metrics tagged with your service.

If nothing shows up:

- Confirm the request returned `200`, not `401`.
- Confirm you're using the key you just minted, not a local or stale one.

**Next:** [Build your first dashboard](/docs/learn/first-dashboard).

You can select **Finish onboarding** in the Cloud Home before creating keys or deploying. The organization returns to its ordinary Home, even when no data has arrived yet. To prepare production later, create keys from **API keys** in the user menu and follow the instructions in your project's README or this guide. Creating a key or opening this guide does not confirm deployment or ingestion.
