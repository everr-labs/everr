title: Dashboards
description: Custom dashboards defined as code, reconciled into Everr with the CLI, and rendered read-only from your ClickHouse data.
---

Everr dashboards are **defined as code**. You write dashboards as YAML or JSON files in a Git repository, then reconcile them into Everr with `everr apply`. The Everr app **renders** them — it runs their queries and draws the charts — but it never edits them. Git is the source of truth.

This is a deliberate, gitops-style model. There is no click-to-edit grid, no save button, no in-app authoring. A dashboard changes when a file changes and you apply it — so dashboards are reviewable in pull requests, versioned with your code, and reproducible across environments.

## The model

A dashboard file follows the [Perses](https://perses.dev) data model — `kind`, `metadata`, and `spec` — with `panels`, `layouts`, and `variables`. Panels run ClickHouse SQL against your telemetry and render it with a visualization (time series, table, or stat). See the [Dashboard spec reference](/docs/dashboards/dashboard-spec) for the full shape.

```yaml
kind: Dashboard
metadata:
  name: api-latency        # the slug; URL becomes /dashboards/<source>/api-latency
spec:
  display:
    name: API Latency
  panels:
    p99:
      kind: Panel
      spec:
        display: { name: p99 latency }
        plugin: { kind: TimeSeriesChart, spec: { unit: ms } }
        queries:
          - kind: ClickHouseSQL
            spec:
              plugin:
                kind: ClickHouseSQL
                spec:
                  query: |
                    SELECT toStartOfMinute(Timestamp) AS ts,
                           quantile(0.99)(Duration) / 1e6 AS p99_ms
                    FROM traces GROUP BY ts ORDER BY ts
  layouts:
    - kind: Grid
      spec:
        items:
          - { x: 0, y: 0, width: 24, height: 8, content: { $ref: "#/spec/panels/p99" } }
```

## Key concepts

- **Source.** Every `everr apply` runs under a `--source` — an identifier you choose for the set of dashboards owned by that repo or directory (for example `platform` or `team-payments`). A source owns its dashboards and nothing else.
- **Identity is `source` + `slug`.** A dashboard's slug comes from `metadata.name` (falling back to the filename). Its URL is `/dashboards/<source>/<slug>`. Two different sources can use the same slug without colliding.
- **Folders come from directories.** The directory a file lives in becomes its folder path in the dashboards tree. There are no folder objects to create or own — move a file, move the dashboard. See [Organizing dashboards](/docs/dashboards/organizing-and-sources).
- **Apply is declarative (delete-by-default).** `everr apply` makes a source's dashboards exactly match its directory tree. A file you add is created, a changed file is updated, and a file you remove is **deleted**. Reconciliation is scoped to the applying source, so it can never touch another source's dashboards. Use `--dry-run` to preview the diff first.
