## Problem Statement

The homepage (packages/docs) ships PostHog for browser analytics: posthog-js initialized in cookieless mode in `src/lib/posthog.ts`, a `PostHogProvider` in `__root.tsx`, and no custom capture calls anywhere. Everr is a telemetry product, and its own homepage sends telemetry to a third party instead of dogfooding the platform. The PostHog data is write-only today (nobody consumes the dashboard), so the vendor buys nothing that Everr-native capture could not provide, while the interesting signals (errors, web vitals, click data) never reach Everr where they could be queried next to everything else.

## Solution

A new `@everr/web-sdk` package (packages/web-sdk) captures browser analytics, errors, and web vitals as plain OTel log records riding the existing OTLP `/v1/logs` ingestion path. The SDK is dual-mode: a strictly cookieless mode (zero browser storage, no visitor id, no consent banner needed) and a consented mode that adds durable identity, `identify()`, and lazy-loaded session replay. The homepage adopts cookieless mode via a side-effect `src/lib/telemetry.ts` module mirroring the web app's telemetry client, runs in parallel with PostHog for about two weeks, and then PostHog is removed.

Session replay, the click heatmap, and browser profiling were each evaluated and scoped: replay is a consented-mode-only capability (never on the homepage; bannerless replay is not GDPR-defensible), the heatmap visualization is deferred, and profiling is cut entirely. (Amended 2026-07-23: plain click/change/submit capture was dropped; interactions are frustration signals only, so no clickmap dataset accrues. Amended 2026-08-03: plain autocapture was re-added for PostHog parity and reconstruct-the-session use; see the Event schema below.)

## User Stories

1. As a homepage visitor, I want zero cookies, zero storage, and no consent banner, so that visiting the docs site tracks nothing about me as an individual.
2. As an Everr developer, I want homepage pageviews, frustration clicks, scroll depth, web vitals, and errors queryable in Everr, so that the homepage is observed with the product itself.
3. As an Everr developer, I want homepage errors grouped and correlated with the page and session they occurred in, so that a broken docs page surfaces like any other error.
4. As a future product user, I want a consented mode with durable visitor identity, `identify()`, and session replay, so that the same SDK can serve the web app and customer deployments.
5. As an SDK integrator, I want "cookieless implies no replay" enforced by the type system and the bundle, so that a privacy promise cannot be broken by a runtime mistake.

## Implementation Decisions

### Event schema (analytics as Logs)

Decided in [Decide the analytics event and identity schema as Logs](../wayfinder/replace-posthog-homepage/tickets/008-analytics-log-schema.md).

- Every analytics signal is a plain OTel log record landing in the existing logs pipeline (`otel_logs` / `app.logs`). No new storage, no person store. EventName carries the event name, Body mirrors it so log browsers show a readable line (amended 2026-07-23, was empty), SeverityNumber is INFO (9). Attribute naming follows OTel semconv where a convention exists (`session.id`, `user.id`, `url.full`, `url.path`, `user_agent.original`, `browser.web_vital.name/value/delta/id`), with the `everr.` prefix everywhere else. (Amended 2026-07-27, second pass: the rule now applies key by key. Semconv-defined keys keep their bare names; every custom key, including custom keys under a semconv event, takes the `everr.` prefix on the full path, e.g. `everr.browser.web_vital.rating`.)
- Event taxonomy, one event name per interaction type: `everr.browser.page_view` (hard navigations plus SPA history changes), `everr.browser.page_leave` (previous-pageview duration plus scroll depth, sent via sendBeacon on pagehide), `everr.browser.interaction.rage_click`, `everr.browser.interaction.dead_click`, `browser.web_vital`. (Amended 2026-07-23: plain `browser.click`/`change`/`submit` were dropped, and the surviving interaction events moved under the `browser.interaction.` namespace; interactions are frustration detection only. Amended 2026-07-27: the naming rule extends to event names, so every event except the semconv-registered `browser.web_vital` and `exception` gained the `everr.` prefix; nothing had shipped, so old names carry no data. Amended 2026-08-03: plain autocapture re-added under the same namespace, one event name per interaction type: `everr.browser.interaction.click` (slow clicks from the Event Timing API, carrying `everr.interaction.duration_ms`, the platform's input-plus-processing time; no coordinates, since Event Timing reports none; filtered to `name === "click"` so one user click yields one record per interactionId), `everr.browser.interaction.change` (form-field only, identity payload, never a value), and `everr.browser.interaction.submit` (targets `event.submitter`). Interim ungated emitter; the eventual breadcrumb model gates raw autocapture behind an "interesting event" (error, slow click, dead/rage click).)
- Cookieless identity: no visitor id at all. No cookies, no storage, no server-side salted hash, nothing derived from IP or user agent (deliberately stronger than PostHog's cookieless mode). A random `session.id` lives in JS memory only, survives SPA navigations, and dies on reload or tab close. Sessions are the analytics unit; unique visitors are simply not a homepage metric.
- Consented identity: same event schema, consent fills the gaps. A random persistent `everr.visitor.id` in localStorage (a device id, never fingerprint-derived), durable 30-minute sessions, `identify(userId, traits)` stamping `user.id` and flattened `user.*` attributes on subsequent events. Profiles are a query-time construct (latest-wins over events); no retroactive merging, no set_once, no cohort store. Consent revocation deletes the stored ids.
- Context envelope on every event (full PostHog parity): `session.id`, `everr.page_view.id`, `url.full`, `url.path`, `everr.referrer.url`, random `everr.event.id` for dedup; resource attributes carry `service.name`, SDK name and version, `user_agent.original`, screen, timezone, language. UTM params stamp as `everr.utm.*` only when present in the landing URL. (Ad-platform click ids were originally specced as `everr.ad_id.*` but are deferred for now; amended 2026-07-23.)
- Frustration payload (rage and dead clicks; amended 2026-07-23, plain clicks are no longer captured): `everr.element.tag`, `everr.element.text` (capped, never input values), `everr.element.selector`, `everr.element.href`, `everr.element.chain` (serialized ancestor chain), `everr.click.x` / `everr.click.y` in page pixels plus viewport size. PostHog privacy guardrails carry over verbatim: input values never captured, password and hidden fields excluded, credit-card and SSN shaped strings dropped, `everr-no-capture` opt-out class. (Amended 2026-08-03: autocapture re-added. The `click` record reuses the same element payload minus coordinates (Event Timing reports none) plus `everr.interaction.duration_ms`. The `change`/`submit` records carry element identity only (tag/selector/chain/href/viewport), no text and no value, by structural guarantee. Rage/dead keep the full payload with coordinates, unchanged. The shared `targetOf` guard (no-capture, password, hidden) gates all three interaction sources; `textOf` runs on the click target but is a no-op for form fields, and is skipped entirely for change/submit.)
- Parity baseline documented in the [autocapture research](../wayfinder/replace-posthog-homepage/research/001-posthog-autocapture-parity.md) (full checklist at the end).

### Web vitals

Decided in [How are web vitals and long tasks best captured](../wayfinder/replace-posthog-homepage/tickets/007-web-vitals-long-tasks.md).

- web-vitals v5 attribution build (onLCP, onCLS, onINP, onFCP, onTTFB). Queue callbacks, flush on visibilitychange hidden (plus pagehide for Safari), dedupe by metric id. (Amended 2026-07-24: the dependency was priced against a hand-rolled capture per the minimalism policy and kept by decision; numbers in the bundle-budget section. No vitals-side queue exists in practice: web-vitals delivers hidden-state callbacks synchronously from a capture-phase visibilitychange listener, so records enter the emitter batch before the exit flush ships it. Dedupe is at-most-once per metric id client-side; a CLS or INP re-report after a tab restore is dropped rather than re-emitted, the page_leave tradeoff, while bfcache restores mint fresh ids and still report.)
- Adopt the OTel semconv `browser.web_vital` event with its four defined fields as bare attribute names (`browser.web_vital.name/value/delta/id`); everything else on the record is custom and lives under the prefix: `everr.browser.web_vital.rating/navigation_type/navigation_id/navigation_url`, attribution auto-derived as `everr.browser.web_vital.<metric>.<field>` with the web-vitals field name snake_cased, e.g. `everr.browser.web_vital.inp.input_delay` and the nested `everr.browser.web_vital.inp.longest_script.source_url`. (Amended 2026-07-27, second pass, superseding the same-day `everr.web_vital.*` decision: the semconv convention is in Development and defines only `name`/`value`/`delta`/`id`, so those four keep their registered names and every other key is everr's own. Snake_case returned with the smallest possible conversion, one uppercase-run regex, so all everr keys share one spelling; if the semconv graduates with real attribute definitions, adopting them is a deliberate migration then, not a guess now.)
- No standalone long-task observer: LoAF data already rides inside INP attribution. Record the landing `url.path` plus the TanStack route pattern at report time; design in `navigation_id` / `navigation_url` for the Soft Navigations API later. (Amended 2026-07-24: the route pattern is sourced from an optional `routePattern` callback on the shared init options and stamped by the envelope as `everr.route.pattern` on every record, sampled per record, so all signals slice by route; the `@everr/web-sdk/tanstack` subpath adapter was later removed, the ten-line register-and-sample bridge is app-owned so the SDK ships no router-specific code. The landing url and path stamp as `everr.landing.url` / `everr.landing.path` on vitals since the envelope's `url.*` follow SPA navigations.)

### Error tracking

Decided in [Decide the error tracking approach for the homepage](../wayfinder/replace-posthog-homepage/tickets/009-error-tracking-approach.md).

- Reuse `@everr/auto-otel-errors/browser` as-is, initialized like the web app (see `packages/app/src/telemetry/client.ts`). Defaults (`window.onerror`, `unhandledrejection`) plus `captureReactError` as the docs router's default error component. Global API patching (`browserApiErrorsIntegration`) stays off.
- Grouping via the existing ClickHouse `errorFingerprint` UDF, unchanged; errors land in `otel_logs` and surface in the existing errors UI. The `error.fingerprint` escape hatch stays available.
- Stacks stay minified: source map symbolication is out of scope (see below).
- The SDK stamps the analytics envelope on every record, errors included, so errors slice by page and session.
- `@everr/auto-otel-errors` gains an optional injected logger on its `init` options (anything with `emit`), so the SDK hands it the hand-rolled emitter directly instead of registering a global OTel provider; the global-provider path stays the default for existing consumers. Its browser path also gets slimmed toward ~2.5-3KB gz by making scrub, rate-limit, and normalization tables tree-shakeable. (Amended 2026-07-23.)
- (Amended 2026-07-27, reversing the previous bullet: the reuse was built, measured, and rejected on the numbers. Even with an injected-logger entry carrying zero OTel bytes, the package's browser pipeline cost ~2.3KB gz inside the SDK core; a native implementation in `packages/web-sdk/src/errors.ts` of exactly what the browser needs, window `error` and `unhandledrejection` listeners, `captureReactError` and `captureError`, and the same 5-per-5s rate limit, costs ~0.4KB gz. `captureReactError` lives in a dedicated `@everr/web-sdk/react` entry (added 2026-07-27) so the core entry stays framework-free and tree-shakes it away. (Trimmed further on 2026-07-27 by decision, function per byte: no scrubbing, error content ships verbatim and scrubbing must return before errors are exposed to external consented-mode adopters, gated in the consented-mode ticket; and no cause-chain rendering, nothing the SDK observes attaches `cause` today.) `@everr/auto-otel-errors` stays untouched at its published surface and remains the server-side path. The duplication is deliberate and bounded by a wire contract: the SDK stamps the identical attribute names (`exception.type` / `exception.message` / `exception.stacktrace`, `everr.error.handled`, `everr.error.mechanism`) so browser and server errors group identically through the errorFingerprint UDF; the SDK also no longer touches that package's global client, so a host app embedding both cannot collide.)

### Session replay (consented mode only)

Decided in [Decide session replay](../wayfinder/replace-posthog-homepage/tickets/010-session-replay-decision.md), grounded in the [GDPR research](../wayfinder/replace-posthog-homepage/research/004-replay-gdpr.md) and the [rrweb storage research](../wayfinder/replace-posthog-homepage/research/005-rrweb-clickhouse-schema.md).

- No replay on the homepage, ever, under the bannerless constraint: recording is regulated terminal access under ePrivacy Art 5(3) even with zero cookies, legitimate interest cannot substitute, and the CNIL draft requires prior consent for all replay purposes. Replay is a consented-mode-only capability, dogfooded on the web app.
- The recording module must not even load without opt-in: `@everr/web-sdk/replay` is a lazy subpath, dynamically imported after consent.
- Masking: Sentry-grade defaults (mask all text, block all media, mask all inputs; explicit allowlist to unmask; password and payment blocking cannot be disabled). Masking is client-side.
- Retention: 30-day TTL default, configurable; sample rate defaulting below 100%; per-session deletion from day one.
- Storage: ClickHouse-only. `app.replay_events` (MergeTree, ORDER BY (tenant_id, session_id, event_time, sequence), payload String CODEC(ZSTD(3)), monthly partitions, TTL part drops) plus `app.replay_sessions` (AggregatingMergeTree summary via incremental MV). SQL sketch in the research doc. No S3 offload below ~100K sessions/month.
- Replay session_id IS the analytics `session.id`: one shared value from the SDK core, joining replay to pageviews, clicks, and errors by equality.

### Click heatmap

(Amended 2026-07-23: plain click capture was subsequently dropped, which voids that decision's data-accrual rationale; a future clickmap effort must reintroduce click capture first and starts from zero data.)

### Browser profiling

Decided in [Decide browser profiling scope](../wayfinder/replace-posthog-homepage/tickets/012-profiling-scope.md): cut entirely. No capture, no ingestion, no reserved module slot in the SDK API. Everr has no profiling surface to land pprof in, minified frames gut readability, and web vitals plus LoAF already cover homepage performance. Capture feasibility facts are preserved in the [profiling research](../wayfinder/replace-posthog-homepage/research/006-browser-profiling-pprof.md) for a future effort.

### SDK packaging, ingestion, and dual modes

Decided in [Decide SDK packaging, ingestion path, and dual privacy modes](../wayfinder/replace-posthog-homepage/tickets/013-sdk-shape-ingestion.md).

- Package: `@everr/web-sdk` at `packages/web-sdk`, depending on `@everr/auto-otel-errors` and `web-vitals`; rrweb only in the replay subpath.
- Ingestion for analytics and errors: a hand-rolled OTLP-JSON emitter (own in-memory queue, batch timer, one fetch POST per flush) on the existing `/v1/logs` path; the SDK ships no OTel runtime packages. The wire format is unchanged, so ingestion and queries cannot tell the difference. Public origin-bound browser key sends to `https://ingest.everr.dev/`; dev builds fall back to the local collector with no key; a keyless production build is a structural no-op. (Amended 2026-07-23: minimalism made the emitter the default rather than the fallback.)
- Replay transport (consented mode only, built when consented mode ships): a dedicated `POST /v1/replay` route on the same ingest host, same public key auth. JSON batches of rrweb events tagged with `session.id` and sequence numbers; the server stamps the tenant and inserts into `app.replay_events`. This is the only net-new server surface in the spec.
- Dual-mode API: `init({ mode: "cookieless" | "consented", ... })` as a discriminated union; the cookieless options type has no replay or identity fields. `init` returns a mode-typed handle: `identify()` and replay hang off the `ConsentedClient` only. `startReplay(client)` requires the `ConsentedClient` argument. "Cookieless implies no replay" holds three ways: zero rrweb bytes in cookieless bundles, a compile-time type error, no runtime capability token. The SDK ships no consent banner; the host's CMP drives transitions, the SDK exposes consented init plus `revoke()`.
- (Amended 2026-07-28: `init` became isomorphic so one call works from shared code in full-stack meta frameworks (Next.js, TanStack Start). On the server (`typeof window === "undefined"`, edge runtimes included) init builds the same emitter pipeline with `logger` and `captureError` wired and returns the same client handle, instead of the previous inert client. Browser signals, the session envelope, and global listeners do not run there: session and page context are per-tab concepts, and process-level handlers (`process.on("uncaughtException")`) alter Node's exit semantics while frameworks already catch request errors and expose hooks (e.g. Next's `onRequestError`) that can call `captureError`. Server resource attributes carry `process.runtime.name`/`process.runtime.version` in place of the browser fields; server records carry no `session.id`. The batch timer is unref'd so a pending batch never holds the process open, and serverless callers flush explicitly. Auth: the hosted ingest denies public origin-bound keys on origin-less requests by the existing policy matrix, so the server-side `ingestKey` must be a secret key; `endpoint` overrides and the dev collector fallback work unchanged. Measured cost in the browser bundle: +116 B gz (7,959 to 8,075 B, ceiling 9KB).)
- Capture is configurable per signal via a disable list: `disable?: true | CaptureSignal[]` on the shared init options (both modes, identical semantics), where `CaptureSignal` is `"pageviews" | "interactions" | "webVitals"`. Everything is on by default, only exclusions are ever named, and `disable: true` turns off all analytics capture. Fixed at init (no runtime toggling). `pageviews` covers page_view and page_leave together; `interactions` covers rage and dead click detection; `webVitals` covers vitals reporting. Errors have no signal key (the auto-otel-errors options govern them), and replay is never a signal (the mode system owns it, keeping "cookieless implies no replay" compile-time). The hard privacy guardrails and the `everr-no-capture` class are not configurable. (Amended 2026-07-22 after the map closed; reshaped from the earlier `capture` boolean/object form on 2026-07-23 under the minimalism north star: only `false` values carried information, so the API names only exclusions.)
- Batching: batch size 32, 5s scheduled delay (the web app's tuning); nothing sent per-interaction. Page exit: an exit flush on pagehide and visibilitychange hidden, riding fetch keepalive only, final payload capped at the 64KB keepalive budget (measured in bytes) with truncation priority errors > page_leave > vitals > interactions. Replay flushes on its own ~5s timer plus the same exit signals. (Amended 2026-07-23: the originally specced sendBeacon fallback was dropped as dead code, since sendBeacon cannot carry the origin-bound key's Authorization header it could never deliver to the hosted ingest, and keepalive support is universal in current browsers.)
- Bundle budget: 9KB gzipped hard ceiling for the cookieless core, 60KB gzipped for the lazy replay chunk, enforced as a CI size gate. Slim-first policy: additions must fit by slimming their own code and their dependencies first; raising the ceiling is a last resort that ships in the same diff as its measured justification. (Amended 2026-07-23: was 30KB, sized around the OTel runtime the SDK no longer ships. Amended 2026-07-24: raised 5KB to 8KB for web vitals, with the measured justification: core alone 2,877 B gz, with the web-vitals v5 attribution build 7,104 B, with the standard non-attribution build 5,028 B; the attribution dependency was kept by decision over a hand-rolled capture, and the core measures 7,664 B gz with the vitals module. Amended 2026-07-27: raised 8KB to 9KB for error capture, with the measured justification: reusing `@everr/auto-otel-errors` cost ~2.3KB gz even after slimming it to an OTel-free injected-logger entry (core measured 9,863 B gz, forcing a 10KB ceiling), so error capture went native in the SDK per the error-tracking amendment and costs ~410 B gz after the same-day trim (no scrub, no cause chains, captureReactError split into the `./react` entry); the core measures 7,858 B gz with errors wired in (capture calls before init() console.warn instead of silently dropping; vitals attribution keys are auto-derived from the attribution object, scalars only, verbatim camelCase spelling, rather than allowlisted and snake_cased, so a web-vitals upgrade may add attribute keys on its own). The ceiling stays 9KB, and consented mode still has to fit under it.)
- Homepage adoption: one SSR-guarded side-effect module `src/lib/telemetry.ts` calling `init({ mode: "cookieless" })` with a docs-specific `service.name`, replacing `src/lib/posthog.ts`. No provider component. Endpoint and key resolution identical to `packages/app/src/telemetry/client.ts` (`VITE_EVERR_PUBLIC_INGEST_KEY`). The docs deployment needs its own public browser key minted with the docs origins allowlisted (origin lists are immutable, so it is separate from the web app's key).

### Rollout and cutover

Decided in [Decide rollout and cutover mechanics for the homepage](../wayfinder/replace-posthog-homepage/tickets/015-rollout-cutover.md).

- Two PRs. PR 1 ships `@everr/web-sdk` on the homepage alongside PostHog; both emit for roughly two weeks. PR 2 removes PostHog after verification.
- Verification is a single manual check by Guido after a few days of overlap: daily pageviews in Everr the same order of magnitude as PostHog `$pageview`; clicks, web vitals, and errors present. No parity bands, no comparison dashboards. Unique visitors and session counts are explicitly not compared (definitionally incomparable under the two cookieless models).
- PR 2 removal inventory: drop `posthog-js` and `@posthog/react` from `packages/docs/package.json`; delete `src/lib/posthog.ts`; unwrap `PostHogProvider` in `__root.tsx`; remove `VITE_POSTHOG_PROJECT_TOKEN` and `VITE_POSTHOG_HOST` from `env.ts`, `.env`, and `.env.example`; remove the same vars from the deployment environment config.
- The PostHog project is kept dormant, not deleted.

## Testing Decisions

- The bundle budgets (5KB core, 60KB replay chunk) are CI gates, not guidelines.
- The dual-mode type guarantees deserve compile-time tests: cookieless init options rejecting replay and identity fields, `startReplay` rejecting a cookieless handle.
- Ingestion is verified with Everr itself during development (events visible via the local collector, then the parallel-run check in production).
- Cutover verification is the manual check described above; no automated cross-system diffing is built.

## Out of Scope

- Shipping the SDK to external customers (product GA). This spec covers the homepage deployment and the SDK shape the web app will dogfood.
- Source map upload and symbolication: net-new server-side infrastructure. Error stacks stay minified.
- Heatmap visualization and plain click capture: both out (clicks amended out 2026-07-23); a future clickmap effort reintroduces capture and rendering together.
- Browser profiling: cut entirely; needs a net-new pprof ingestion and viewing surface plus symbolication to be useful.
- Consented-mode server work beyond the spec'd shape: the `/v1/replay` route and replay tables are built when consented mode ships, not for the homepage cutover.
