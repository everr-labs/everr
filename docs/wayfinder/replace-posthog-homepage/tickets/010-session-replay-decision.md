## Question

Given the GDPR findings and the rrweb storage research: does replay run at all on the strictly cookieless homepage, or only in the consented product mode? Decide masking defaults, retention, the ClickHouse schema, and how replay sessions link to the analytics session identity.

## Resolution

1. **No replay on the homepage.** The GDPR research (research/004-replay-gdpr.md) closes every consent-free route: recording is regulated terminal access under ePrivacy Art 5(3) even with zero cookies, legitimate interest cannot substitute, and the CNIL draft requires prior consent for all replay purposes. Bannerless is a hard constraint, so the homepage emits zero replay data. Replay ships in the SDK as a **consented-mode-only capability**: the recording module must not even load without opt-in (lazy init after consent, Sentry pattern). Replay dogfooding happens on a consented surface (the web app), not the homepage.
2. **Masking: Sentry-grade defaults.** Mask all text, block all media, mask all inputs by default; explicit allowlist to unmask specific elements; password and payment-field blocking cannot be disabled. Masking is client-side, so masked data never leaves the browser.
3. **Retention and collection limiting.** 30-day TTL default (within the CNIL's "few months" band for UX and error purposes), configurable per deployment; configurable sample rate defaulting below 100%; per-session deletion supported from day one to honor erasure requests.
4. **Storage: the researched ClickHouse-only schema, adopted as specced** (research/005-rrweb-clickhouse-schema.md, already vetted against clickhouse-best-practices): app.replay_events (MergeTree, ORDER BY (tenant_id, session_id, event_time, sequence), payload String CODEC(ZSTD(3)), monthly partitions, TTL part drops) plus app.replay_sessions (AggregatingMergeTree summary via incremental MV). No S3 offload; revisit only past ~100K sessions/month, and the summary table already matches the shape a blob migration would keep.
5. **Identity link: replay session_id IS the analytics session.id** from the analytics-schema decision, one shared value generated by the SDK core. Replay joins to pageviews, clicks, and errors by direct equality; a recording spanning a 30-minute session rollover starts a new replay session.

Constraint for the SDK-shape ticket: the replay module is consent-gated and lazy-loaded; the dual-mode API must make "cookieless mode implies no replay" structurally true, not a runtime footgun.
