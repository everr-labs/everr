# Product

## Register

product

## Users

Everr is used by developers, platform engineers, and teams that need to understand what code does while it runs. Users are often debugging, reviewing CI failures, watching production behavior, or setting up observability as code without a dedicated telemetry team.

## Product Purpose

Everr makes OpenTelemetry signals useful where engineering work already happens: local development, CI, and production. It turns telemetry into queryable, reviewable, repo-owned resources so teams can validate software behavior quickly and keep runtime context close to the work.

## Brand Personality

Clear, capable, direct. The product should feel like a serious developer tool that removes ceremony from observability without hiding the truth from expert users.

## Anti-references

Avoid dense dashboard walls that require observability specialists to interpret, click-built configuration that cannot be reviewed, decorative SaaS chrome, and generic wrapper experiences that obscure the underlying telemetry model.

## Design Principles

- Lead with the operational answer, then reveal the mechanism.
- Explain advanced concepts in plain language without patronizing experts.
- Keep configuration and identity visible, but secondary to current status.
- Prefer quiet, scannable surfaces over decorative panels.
- Make observability as code feel reviewable, predictable, and trustworthy.

## Accessibility & Inclusion

Use WCAG AA as the baseline. Status must not rely on color alone. Dense data surfaces need keyboard-accessible links and actions, readable contrast, stable layout, and reduced-motion-safe interactions.
